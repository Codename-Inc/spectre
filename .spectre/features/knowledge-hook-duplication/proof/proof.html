R4 — duplicated bytes removed

On HEAD the absolute CLI path and absolute project dir were repeated in a load command for every record.

HEAD — per record

### Knowledge record: feature-zulu
- ID: feature-zulu
- Version: 1
- Use when: …
- Activation cues: …
- Load exact record: '<cli>' load
  'feature-zulu' --project-dir '<dir>'

3 records → 3 load commands · 3692 chars

Working tree — hoisted once

Load a record by copying its ID
verbatim into this command:

'<cli>' load '<ID>' --project-dir '<dir>'

- ID: feature-zulu (v1) — Use when: …
  Cues: …

3 records → 1 load command · 3131 chars

On this repository's own 4-record store the payload falls from 4505 to 3774 characters. The marginal cost per record falls from 476 to 233 characters, so the saving grows with the number of records and more records fit under the size cap before truncation. Character-to-token figures quoted elsewhere are 4-chars-per-token estimates, not host tokenizer output.

R6 — the hoisted template still works

Removing per-record commands means the agent must build the command itself. That risk was proven, not assumed: the template line was extracted from the emitted payload, an ID substituted verbatim, and the result executed through a real shell. 

template   '<cli>/knowledge-cli.mjs' load '<ID>' --project-dir '<dir>'
executed   …load 'feature-zulu'…
exit code  0
returns    record body                        ✓
           SPECTRE_KNOWLEDGE_RESOURCE_LOCATIONS ✓  (record directory + verified resource paths)

Resources and references are delivered by the load itself (loader.mjs formatKnowledgeLoadHuman), which is why the registry does not need to carry them. The ID stays verbatim as the first token of its line, so no derivation is required. Limitation: the fixture records carry no supporting resource files, so the manifest is empty — the delivery mechanism is proven, a populated manifest is not.

Limitations
